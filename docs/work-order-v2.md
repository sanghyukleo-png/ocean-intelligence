## 0. 미션

이 사이트를 **"조선 영업기획 데모"에서 "정유·석유화학 해상 오퍼레이션 데스크"로** 끌어올린다.

판정 기준은 두 가지다.

1. **첫 5초**: 처음 접속한 사람이 "개인 포트폴리오"가 아니라 "돈 받고 파는 B2B 제품"이라고 느낀다. 로고·배경·타이포·모션·비율이 그 수준이어야 한다.
2. **실무 5분**: S-OIL·GS칼텍스의 용선/선적 오퍼레이터, 수출입 영업 담당자가 자기 업무 숫자를 넣어 봤을 때 결과를 믿을 수 있고, 내일 또 열어 볼 이유가 있다.

둘 중 하나만 되면 실패다. 디자인(Phase 1~2)을 먼저 끝내고 기능(Phase 3~6)을 올린다.

## 1. 반드시 지킬 규칙

1. **`AGENTS.md` 준수**: 이 저장소의 Next.js는 16.3.1이다. 코드를 쓰기 전에 `node_modules/next/dist/docs/`에서 해당 API 문서를 먼저 읽는다. 학습 데이터 속 Next.js 관례를 그대로 쓰지 않는다.
2. **계산은 코드, 설명은 AI**: 모든 숫자는 `src/lib/`의 순수 TypeScript 함수가 만든다. LLM이 숫자를 만들거나 바꾸지 않는다. (기존 원칙 유지)
3. **데이터 등급 표기**(핵심 지표는 11장에 따라 LIVE만 허용): 화면의 모든 수치에 다음 셋 중 하나의 배지를 붙인다 — `LIVE`(외부 소스·수집 시각 표기) / `입력값 계산`(사용자 입력으로 산출) / `DEMO`(시뮬레이션). 데모 수치를 실시간처럼 보이게 하지 않는다.
4. **지어내지 않는다**: 부두 제한(LOA·흘수 등), 항로 거리, 용선계약 조항 기본값은 출처 없이 "사실"로 적지 않는다. 사용자가 수정 가능한 프리셋으로 두고 "예시값 · 실제 터미널 규정/C/P 확인"을 표기한다.
5. **계산 엔진에는 테스트를 붙인다**: `vitest`를 추가하고, 아래 5장 각 모듈의 "검증 케이스"를 테스트로 작성한다. 테스트가 통과하지 않으면 UI를 만들지 않는다.
6. **기존 라우트는 깨지지 않는다**: `/market` `/vessels` `/compare` `/opportunities` `/analytics` `/about` URL 유지.
7. **Phase가 끝날 때마다** `npm run build` + `npm run lint` + 테스트 통과, 그리고 1440px·390px 스크린샷으로 육안 확인. 커밋은 Phase 단위, 푸시는 사용자 확인 후.

## 3. 디자인 시스템 (Phase 1)

방향: **해도(海圖)와 관제 화면** — 어두운 잉크 네이비 위에 얇은 선, 정밀한 숫자, 절제된 단일 강조색. 참고 감각은 Linear·Vercel·Stripe의 정밀함 + 해도/ECDIS의 선 언어. 네온, 보라 그라디언트, 과한 글래스모피즘, 3D 지구본 금지.

### 3.1 컬러 토큰 (`globals.css` 교체)

다크를 기본으로 하고 라이트 테마를 함께 제공한다(인쇄·정산서 출력은 라이트).

```css
:root {                      /* dark (default) */
  --bg:        #070B14;      /* 페이지 */
  --bg-raised: #0C1220;      /* 카드 */
  --bg-inset:  #060911;      /* 입력창·표 내부 */
  --line:      #1B2437;      /* 기본 경계 */
  --line-strong:#2A3650;
  --fg:        #E8EDF7;
  --fg-muted:  #8A96AD;
  --fg-faint:  #56617A;
  --accent:    #4FD1C5;      /* 유일한 브랜드 강조: 항로선·CTA·활성 탭 */
  --accent-ink:#04201D;      /* accent 위 글자 */
  --up:        #3DDC97;
  --down:      #FF6B6B;
  --warn:      #F5B94A;      /* 체선·기한 임박 */
  --info:      #6EA8FE;
}
[data-theme="light"] { /* 같은 이름으로 재정의: bg #F6F8FB, raised #FFFFFF, fg #0B1220, accent #0E8F84 … */ }
```

- 주황 계열 전면 제거. 점수 등급 색도 위 토큰으로 재매핑.
- 본문 대비 WCAG AA(4.5:1) 이상. `--fg-muted`를 12px 미만 텍스트에 쓰지 않는다.
- 헤더에 테마 토글. `prefers-color-scheme` 존중, 선택값은 `localStorage`.

### 3.2 타이포그래피

- 한글·UI: **Pretendard Variable** (`next/font/local`, woff2 서브셋, `display: swap`).
- 숫자·코드: **JetBrains Mono** 또는 **IBM Plex Mono** (`next/font/google`), `font-variant-numeric: tabular-nums slashed-zero`.
- 전역: `word-break: keep-all; overflow-wrap: anywhere; text-wrap: pretty;` 제목은 `text-wrap: balance`.
- 유동 스케일(1440 기준, `clamp`):

| 토큰 | 값 | 용도 |
|---|---|---|
| display | `clamp(2.5rem, 1.2rem + 4.2vw, 4.75rem)` / 1.04 / -0.03em / 700 | 히어로 |
| h1 | `clamp(1.75rem, 1.3rem + 1.4vw, 2.5rem)` / 1.15 / -0.02em | 페이지 제목 |
| h2 | 1.25rem / 1.3 / -0.01em / 600 | 섹션 |
| body | 0.9375rem / 1.6 | 본문 |
| label | 0.6875rem / 1 / +0.08em / 600 / uppercase | 필드 라벨·배지 |
| num-xl | `clamp(2rem, 1.4rem + 2vw, 3.25rem)` mono 600 | 핵심 결과값 |

### 3.3 로고·브랜드 자산

lucide `Anchor` 제거. **직접 그린 SVG**로 교체한다.

- 심볼 컨셉: 원(O) 안에 경위선 2~3개가 지나가고, 그중 한 줄이 대권항로처럼 휘어 원을 빠져나가는 형태. 24px에서도 뭉개지지 않게 선 굵기 1.75px 기준, 획 3개 이내.
- 워드마크: `OCEAN` 600 + `INTELLIGENCE` 400, 자간 +0.14em, 두 단어 사이 얇은 구분.
- 산출물: `src/components/brand/logo.tsx`(심볼·워드마크·조합, `currentColor`), `app/icon.svg`, `app/apple-icon.png`(180), `app/opengraph-image.tsx`(1200×630, 히어로 축소판), `public/` 안의 create-next-app SVG 5개 삭제.
- 3안을 만들어 스크린샷으로 비교 보고 후 1안 확정.

### 3.4 배경·깊이

- 페이지: `--bg` 단색 위에 ① 48px 간격 해도 격자(1px, 불투명도 4%), ② 상단에서 내려오는 방사형 광원 1개(accent 6%), ③ 미세 노이즈(SVG feTurbulence, 3%). 스크롤해도 고정(`background-attachment: fixed` 대신 `position: fixed` 레이어).
- 카드: `--bg-raised` + 1px `--line` + 상단 1px 하이라이트(`inset 0 1px 0 rgb(255 255 255 / .04)`). 그림자 대신 경계와 명도로 깊이를 만든다.
- 히어로 배경: `<canvas>` 또는 SVG로 그린 **등심선(bathymetric contour) + 주요 항로 호(arc)**. 세부는 4.1.

### 3.5 레이아웃·비율·배율

- 컨테이너: `max-width: 1440px`, 좌우 여백 `clamp(1rem, 4vw, 3rem)`. 12컬럼 그리드, 거터 24px(모바일 16px).
- 간격은 4px 배수만(4·8·12·16·24·32·48·64·96). 섹션 간격 `clamp(3rem, 6vw, 6rem)`.
- 모서리: 카드 12px, 입력·버튼 8px, 배지 999px. 한 화면에 반경 3종 이내.
- 검증 뷰포트: **360 / 390 / 768 / 1024 / 1280 / 1440 / 1920 / 2560**. 추가로 브라우저 배율 80%·110%·125%, DPR 1·2에서 줄바꿈 깨짐·가로 스크롤·1px 선 번짐이 없어야 한다.
- 1920 이상에서는 컨테이너를 넓히지 말고 히어로 배경만 풀블리드로 확장한다. 2560에서 본문이 한쪽으로 쏠려 보이지 않게 중앙 정렬 유지.
- 표·정산서는 모바일에서 카드로 접지 않고 가로 스크롤(첫 열 고정).
- 터치 타깃 최소 44px. 입력 필드 높이 40px(데스크톱)·44px(모바일).

### 3.6 모션

라이브러리: `motion`(구 framer-motion) 하나만 추가. 원칙은 **빠르고, 짧고, 의미 있게**.

- 이징: 진입 `cubic-bezier(0.16, 1, 0.3, 1)`, 종료 `cubic-bezier(0.7, 0, 0.84, 0)`. 지속 160~480ms. `transform`·`opacity`만 애니메이션(레이아웃 속성 금지).
- **첫 진입 시퀀스(총 1.4초 이내)**: ① 0ms 배경 격자 페이드 → ② 120ms 로고·내비 → ③ 200ms 히어로 제목이 줄 단위 마스크 리빌(40ms 간격) → ④ 500ms 항로 호가 `stroke-dashoffset`으로 그려짐(900ms) → ⑤ 700ms 라이브 티커 숫자 카운트업 → ⑥ 900ms CTA.
- 스크롤 리빌: 뷰포트 진입 시 12px 상승 + 페이드, 형제 요소 60ms stagger, 1회만.
- 숫자: 결과값이 바뀌면 이전 값에서 새 값으로 320ms 보간(tabular-nums라 폭이 흔들리지 않는다).
- 차트: 선은 좌→우 드로잉, 막대는 아래→위. 재계산 시 깜빡임 없이 모핑.
- 페이지 전환: View Transitions API(Next 16 문서에서 지원 방식 확인 후 적용), 미지원 브라우저는 즉시 전환.
- 호버: 카드 경계가 `--line-strong`으로, 포인터 위치를 따라가는 약한 스포트라이트(accent 8%, radial). 버튼은 1px 눌림.
- `prefers-reduced-motion: reduce`에서는 전부 즉시 표시. 무한 반복 애니메이션은 히어로의 항로 점 이동 하나만 허용(화면 밖이면 정지).
- 성능 예산: LCP < 2.0s, CLS < 0.02, 히어로 애니메이션 60fps(모바일 4x CPU 스로틀에서 50fps 이상). 히어로 캔버스는 `requestIdleCallback` 이후 초기화, 초기 JS 추가분 60KB(gzip) 이내.

### 3.7 공용 컴포넌트 (`src/components/ui/`)

`Button`(primary/secondary/ghost, sm/md), `Field`(라벨·단위 접미사·오류·도움말), `NumberInput`(천단위 표시, 화살표키 증감, 단위 고정), `DateTimeInput`(현지시각, 24h), `Select`, `Segmented`, `Slider`(커스텀 트랙), `Tabs`, `Badge`(LIVE/계산/DEMO/상태), `Stat`(라벨+큰 숫자+델타), `DataTable`(고정 헤더·정렬·우측 정렬 숫자), `Tooltip`(용어 설명), `Sheet`(모바일 입력 패널), `Toast`(복사 완료), `EmptyState`, `Skeleton`.

## 5. 오퍼레이션 모듈 (Phase 3~5)

공통 요구: 입력값은 URL 쿼리에 직렬화(링크 공유)하고 `localStorage`에 최근 10건 저장. 결과는 **복사 / 인쇄용 정산서(A4 라이트 테마, `@media print`) / CSV** 내보내기. 모든 기본값 옆에 "C/P 확인" 툴팁.

### 5.1 Laytime · Demurrage — `src/lib/laytime.ts` (최우선)

오퍼레이터가 가장 자주 손으로 하는 계산이다. SOF 시각을 넣으면 정산서가 나온다.

**입력**
- 계약: 허용 Laytime(총 시간 고정 **또는** 양하율 기준 `수량 ÷ MT/hr`), Reversible 여부(선적·양하 합산/분리), Demurrage rate($/day, pro rata), Notice time(기본 6h), Laycan(시작·종료), 문서 대기 허용(기본 3h, 호스 분리 후), 클레임 제출 기한(기본 90일, 양하 완료일 기준).
- 항구별 SOF(여러 항구 추가 가능): NOR tendered, Anchored, Anchor aweigh, Pilot on board, All fast, Hoses connected, Commenced, Completed, Hoses disconnected, Documents on board, Sailed. 현지시각 + UTC 오프셋.
- 공제 항목(여러 건): 시작·종료·사유·**계산 비율(0% / 50% / 100%)** — 기상, 묘박지→부두 이동(shifting), 본선 귀책, 터미널 귀책 등.

**규칙(모두 스위치로 끌 수 있는 기본값)**
- 개시: `min(NOR + notice time, All fast)`. NOR이 laycan 시작 전이면 개시 시점은 laycan 첫날 06:00 또는 작업 개시 중 빠른 쪽(옵션).
- 종료: Hoses disconnected. 문서 대기가 허용 시간을 넘으면 초과분을 가산(옵션).
- Shifting(anchor aweigh → all fast)은 기본 제외.
- Laytime 소진 후 발생한 공제는 "once on demurrage, always on demurrage" 스위치에 따라 처리(기본: 50% 항목만 반감 유지, 나머지는 계속 가산).
- 결과: 허용 / 항구별 사용 / 총 사용 / 초과 시간 / Demurrage 금액 / 클레임 기한일과 D-day.

**화면**: 좌측 SOF 입력(붙여넣기 지원 — "1200 NOR tendered" 같은 줄 단위 텍스트를 파싱), 우측에 **타임라인 바**(laytime 구간 초록, 공제 회색 빗금, 체선 구간 warn 색)와 정산 표. 하단에 영문 Laytime Statement와 Demurrage Claim 커버레터 초안(템플릿, 복사 버튼).

**검증 케이스(테스트 필수)**
- NOR 01일 08:00, All fast 01일 20:00, 허용 72h, 호스 분리 05일 02:00, 공제 없음 → 개시 01일 14:00, 사용 84h, 초과 12h, rate $30,000/day → **$15,000**.
- 위 조건에 01일 18:00~20:00 shifting 제외 → 사용 82h, 초과 10h → **$12,500**.
- 체선 구간에 기상 4h(50%) → 체선료에서 2h분 차감.
- 2개 항구 reversible/non-reversible 각각.
- 자정·월말·UTC 오프셋이 다른 두 항구.

### 5.2 운임 — `src/lib/freight.ts`

- Worldscale: `운임 = Flat($/MT) × WS/100 × 수량`. 최소 수량 미달 시 deadfreight, 초과분은 overage 비율(기본 50%) 적용. 고정·변동 differential 가산.
- Lumpsum ↔ $/MT ↔ $/bbl 상호 환산(수량·bbl/MT 계수 입력).
- 수수료(address commission, brokerage) 반영한 순운임.
- **옵션 비교표**: 최대 4안(예: MR 35kt vs LR1 55kt)을 나란히 놓고 톤당 운임·총액·화물가 대비 비중 비교.
- Flat rate는 유료 데이터이므로 **사용자 입력**. 예시값에는 DEMO 배지.
- 검증: Flat 10.00, WS 150, 35,000MT → $525,000 / $15.00/MT. 최소 30,000·실제 33,000·overage 50% → 30,000×15 + 3,000×7.5.

### 5.3 넷백 · 아비트라지 — `src/lib/netback.ts`

- 수출: `FOB 넷백 = CFR 도착가 − 운임 − 보험 − 감모(loss %) − 검정비 − 금융비용(가격 × 금리 × 결제일수/360) − 체선 충당 − 기타`.
- 도착지 최대 5개를 표로 비교하고 넷백 순으로 정렬. 내수 기준가 대비 프리미엄, **손익분기 운임**(이 운임 이하면 아비트라지 열림) 표시.
- 수입 방향(`도착 원가 = FOB + 운임 + 보험 + 관세 + …`) 토글.
- 가격은 전부 사용자 입력. 민감도: 운임 ±$5, 도착가 ±$10 히트맵.

### 5.4 수량·가격 환산 — `src/lib/quantity.ts`

- 밀도 환산: API ↔ 비중(60/60°F) ↔ 밀도 15°C. `API = 141.5/SG − 131.5`.
- **VCF(ASTM D1250-80 Table 54A/54B/54D 계산식)**: `α = (K0 + K1·ρ)/ρ²`, `VCF = exp(−α·Δt·(1 + 0.8·α·Δt))`, `Δt = t − 15`.
  - 54A 원유: K0 613.9723, K1 0
  - 54B 제품: 밀도 ≤770 → 346.4228 / 0.4388; 770~788 → `α = −0.00336312 + 2680.3206/ρ²`; 788~839 → 594.5418 / 0; ≥839 → 186.9696 / 0.4862
  - 54D 윤활유: 0 / 0.6278
  - **상수와 구간 경계는 구현 전에 공개 자료로 재확인하고, 공표된 표 값 3개 이상과 소수 4자리까지 맞는지 테스트한다.** 맞지 않으면 기능을 보류하고 보고한다.
- 흐름: 관측 부피(GOV) × VCF → GSV(15°C) → 중량(진공) = GSV × 밀도, 중량(공기 중) = GSV × (밀도 − 0.0011) → bbl@60°F(환산계수는 입력 가능 필드로 두고 기본값의 출처 표기).
- 가격: $/bbl ↔ $/MT ↔ ¢/gal ↔ 원/L (bbl/MT 계수·환율 입력, 환율은 LIVE 값 불러오기 버튼).
- 선적 수량 대조: B/L 수량 vs 본선 수량(VEF 적용) vs 양하 수량 → 차이 %와 통상 허용 범위 초과 여부.
- 하단 고정 문구: "정산은 검정기관(Surveyor) 성적서 기준. 본 계산은 검산용."

### 5.5 딜 타임라인 · 서류 — `src/lib/dealSchedule.ts`

- 입력: Laycan, 예상 B/L일, 가격 조항(B/L 전후 N일 평균 / 선적월 평균 / 전월 평균 / 고정가), 결제 조건(B/L 후 N일 T/T, L/C at sight·usance), 인코텀즈, 노미네이션 리드타임.
- 출력: 날짜순 체크리스트 — 선박 노미네이션 기한, laycan 축소 통지, L/C 개설 기한, 서류 지시(Documentary Instruction) 송부, 가격 산정 기간(주말 제외, 공휴일은 "가격 고시 기관 휴일 확인" 표기), 가송장·확정송장, 결제 만기(은행 휴무일이면 조정 규칙 선택), 체선료 클레임 기한.
- `.ics` 내보내기(캘린더 등록)와 체크리스트 복사.
- 인코텀즈·결제 조건별 선적 서류 체크리스트(B/L, Commercial Invoice, Certificate of Quality/Quantity/Origin, Cargo Manifest, Tank Inspection Cert, Ullage Report, Time Sheet, Master's Receipt 등) — 항목별 한 줄 설명과 발행 주체.
- 포뮬러 프라이싱 계산기: 일별 고시가를 붙여넣으면 산정 기간 평균 + 프리미엄 → 단가·송장 금액, 가송장 대비 정산 차액.

- 가짜 항로 추적(`voyageDemo.ts`, `voyage-map.tsx`)은 삭제.

### 5.8 항차 견적 · TCE — `tce.ts` 보강

- 구간: Ballast → Load port → Laden → Discharge port. 구간별 거리·속력·일일 소모량(laden/ballast 분리), 정박 중 소모량(idle/작업), 항구 일수, ECA 구간의 MGO 분리.
- `TCE = (운임 수익 − 수수료 − 벙커 − 항비 − 운하 − 기타) ÷ 총 항차일수`(공선·정박 포함).
- CO₂ 배출량(연료별 배출계수는 IMO 지침 값을 확인 후 상수로) 표시.
- 거리는 사용자 입력이 기본. 자주 쓰는 구간 프리셋은 **공개 거리표로 검증한 뒤에만** 넣고 "추정치" 표기.
- 민감도: 운임 × 벙커 2차원 히트맵, 속력별 TCE 곡선.
- 기존 대비 회귀 테스트: 정박 소모 0·공선 0으로 두면 기존 결과와 동일해야 한다.

### 5.9 시황 `/market` 재구성

- 상단 LIVE: Brent, WTI, USD/KRW, (가능하면) 벙커가. 무료·무키 소스를 후보별로 **실제 Vercel 서버에서 호출 테스트**한 뒤 채택하고, 이용약관상 문제 있는 스크래핑은 쓰지 않는다. 서버 Route Handler에서 수집·캐시(30분), 실패 시 마지막 성공값 + 수집 시각 표시.
- 뉴스: 국문 키워드(정제마진, 유조선 운임, 호르무즈, 석유화학 등) RSS + 기존 영문 피드, 출처·시각 표기, 탭 필터.
- 탱커 운임지수 등 유료 데이터는 수집하지 않는다. "직접 입력 → 내 대시보드에 고정" 카드로 제공.
- 기존 조선 지표 8개는 `/opportunities` 쪽으로 이동하고 DEMO 배지 유지.

### 11.1 "실시간"의 정의 — 지표마다 원천의 발표 주기가 다르다

화면에는 지표마다 **발표 주기 · 원천 기준 시각 · 우리 수집 시각**을 함께 표기한다. 원천이 주 1회인 지표를 초 단위로 움직이게 만들지 않는다.

| 지표 | 원천 발표 주기 | 우리 갱신 주기 | 비고 |
|---|---|---|---|
| 원유(Brent·WTI·Dubai) | 장중 연속 | 5~15분 | 지연 시세면 "15분 지연" 표기 |
| USD/KRW | 장중 연속 또는 일 1회 | 소스에 맞춤 | |
| 벙커유(VLSFO·HSFO/IFO380·MGO) — 싱가포르·부산·로테르담·푸자이라 | 일 1회~수회 | 1~3시간 | 항구별 값, 전일 대비, 30일 추이 |
| SCFI (종합 + 주요 항로) | **주 1회(금요일)** | 금요일 발표 직후 자동 수집, 이후 일 1회 확인 | "주간 지수 · 다음 발표 D-n" 표기 |
| 기타 운임(KCCI 등 국내 공공 지수) | 주 1회 | 발표일 수집 | 공공 소스가 있으면 SCFI와 나란히 |
| 글로벌 선박 현황(AIS) | 초 단위 | 서버에서 1~5분 집계 | 11.3 |
| 기상청 해상 특보·예비특보 | 수시 발표 | 10분 | 11.4 |
| 기상청 해상예보(단기)·중기해상예보 | 일 2~8회 | 1시간 | 11.4 |

### 11.2 데이터 수집 구조

```
Vercel Cron → /api/ingest/[source] → 정규화 → 저장소(시계열) → /api/data/[metric] → 화면
```

- **소스 어댑터**(`src/lib/sources/<name>.ts`): `fetch → parse → validate → normalize`를 한 파일에. 반환 형식 통일: `{ metric, value, unit, asOf(원천 시각), fetchedAt, source, sourceUrl }`.
- **저장소**: 시계열이 필요하다(추이 차트, 실패 시 마지막 성공값). Vercel에서 쓸 수 있는 무료 티어 중 하나를 고른다 — Supabase(Postgres) 권장, 대안은 Upstash Redis / Vercel Blob. 선택 근거를 보고한다.
- **스케줄**: `vercel.json`의 cron. 현재 플랜의 cron 빈도 제한을 문서로 확인하고, 제한에 걸리면 "요청 시 갱신(stale-while-revalidate) + 최소 간격" 방식으로 보완한다.
- **검증**: 값이 직전 대비 비정상(예: ±30% 이상)이면 저장하지 않고 경고 로그. 파싱 실패와 빈 응답을 구분해 기록.
- **상태 페이지 `/status`**: 소스별 마지막 성공 시각, 연속 실패 횟수, 응답 시간. 헤더의 작은 상태 점(정상/지연/실패)이 여기로 연결된다.
- **키 관리**: 모든 API 키는 Vercel 환경변수. `.env.example`에 필요한 키 이름과 발급처를 적는다. 키가 없는 소스는 화면에 "API 키 미설정"으로 표시한다(숨기지 않는다).

**소스 선정 절차(지표마다 반드시 수행)**
1. 후보를 2~3개 조사한다: 공식·공공 API > 무료 티어가 있는 상용 API > 공개 웹페이지 순으로 우선.
2. 이용약관에서 자동 수집·재게시 허용 여부를 확인한다. **약관이 금지하는 스크래핑은 쓰지 않는다.**
3. 배포 환경(Vercel 서버)에서 실제로 호출되는지 테스트한다. 로컬에서 되는 것으로 판단하지 않는다.
4. 결과를 표로 보고한다: 소스 / 무료 여부 / 키 필요 / 갱신 주기 / 약관 / 채택·탈락 사유.

**미리 알아둘 제약**
- 벙커유와 SCFI는 완전 무료·무제한 공식 API가 없을 가능성이 높다. 무료 티어 API(월 호출 제한)나 발표 기관 공개 페이지가 현실적인 후보다. 현재 코드의 `shipandbunker.com` HTML 정규식 수집은 약관과 안정성 모두 문제가 될 수 있으니 재검토 대상이다.
- 무료 소스로 약관을 지키며 수집할 방법이 없는 지표는 **임의로 대체하지 말고 사용자에게 보고**한다(유료 API 비용, 대체 지표 제안 포함).
- Platts·Argus·Baltic·Worldscale flat은 여전히 수집 금지(9장).

### 11.3 글로벌 선박 현황 (실제 AIS)

"가짜 항로 추적"을 지우는 대신 **실제 AIS 기반 집계**를 넣는다.

- 소스 후보: 무료 AIS 스트림 API(WebSocket, 키 발급 필요) 등. 커버리지는 육상 수신 기반이라 원양은 비는 구간이 있다 — 화면에 "육상 AIS 수신 범위 기준" 표기.
- WebSocket은 서버리스 함수에서 상시 연결을 유지할 수 없다. 두 방식 중 택일해 보고한다: ① cron이 짧게(수십 초) 접속해 관심 해역 스냅샷을 수집·집계, ② 브라우저가 직접 접속(키 노출 문제 확인 필수 — 노출되면 불가).
- **보여줄 것(개별 선박 추적이 아니라 오퍼레이터가 쓰는 집계)**
  - 국내 주요항 묘박지·항내 탱커 척수(선종·크기 구간별)와 24시간 증감 → 체선 조짐 지표
  - 주요 초크포인트 통과 현황: 호르무즈, 말라카·싱가포르 해협, 대한해협 (방향별 탱커 척수)
  - 지도: 관심 해역 박스 안의 탱커 점 표시(확대 시), 축소 시에는 밀도만
  - 선명·IMO 검색 → 최근 수신 위치(수신 시각 표기). Q88 화면에서 바로 호출
- 관심 해역 박스와 항만 묘박지 폴리곤 좌표는 공개 해도·항만 고시로 확인해 `src/data/geo/`에 두고 출처를 주석으로 남긴다.
- 선종 분류는 AIS ship type 코드 기준(탱커 80번대). 크기 구간은 AIS 치수(길이·폭)로 추정하고 "추정" 표기.

### 11.4 국내 주요항 클로징 위험도 (기상청 연동)

오퍼레이터가 매일 아침 확인하는 것: "이번 주 우리 배가 들어갈 수 있나."

**데이터 소스 — 기상청 공식 API만 사용** (공공데이터포털 `data.go.kr` 또는 기상청 API허브 `apihub.kma.go.kr`, 키 발급 필요)
- 기상특보 조회: 발효 중 특보, **예비특보**, 특보 통보문
- 단기 해상예보(해상 예보구역별 풍향·풍속·파고)
- 중기해상예보(3~10일 파고 등)
- 태풍 정보
- 서비스명·엔드포인트·응답 필드·해상 예보구역 코드는 **API 명세 문서를 받아 확인한 뒤 구현**한다. 추측으로 필드명을 쓰지 않는다. Open-Meteo는 보조(시간별 곡선)로만 쓴다.

**대상 항만**(각 항만을 해당 기상청 해상 예보·특보구역에 매핑 — 매핑표를 `src/data/kmaPortZones.ts`에 만들고 기상청 구역 정의로 검증)
- 울산·온산(SPM 포함), 여수·광양, 대산, 인천, 평택·당진, 부산, 포항, 군산, 목포, 마산, 동해·묵호, 제주
- 정유·석화 관련 항(울산·온산, 여수·광양, 대산, 인천)을 목록 상단에 고정

**위험도 산출 — 결정론적 규칙** (`src/lib/portRisk.ts`, 테스트 필수)

| 등급 | 조건(기본값, 설정에서 수정 가능) |
|---|---|
| **통제 중 가능성 높음** | 해당 구역에 풍랑경보·태풍경보·태풍주의보 발효 |
| **높음** | 풍랑주의보 발효, 또는 24시간 내 풍랑·태풍 예비특보 |
| **주의** | 48시간 내 예비특보, 또는 단기예보 풍속·파고가 사용자 임계값 초과, 또는 안개(저시정) 특보·예보 |
| **관찰** | 중기해상예보(3~10일)에서 높은 파고 구간 존재, 또는 태풍 예상 진로가 한반도 인근 |
| **정상** | 해당 없음 |

- 특보 발표 기준(풍속·파고 수치)은 기상청 공식 기준을 문서에서 확인해 상수로 넣고 출처를 주석에 남긴다.
- 선박 크기별로 통제 기준이 다르다(소형선이 먼저 통제). 입력 선박의 크기 구간을 선택하면 등급 해석 문구가 달라지게 한다. 항만별 실제 통제 기준(항만 운영 세칙, VTS 고시)은 공개 자료로 확인된 것만 넣고, 없으면 "항만별 기준 확인 필요"로 둔다.
- 등급마다 **근거를 그대로 노출**한다: 어떤 특보·예보가, 언제 발표되어, 언제부터 언제까지 유효한지, 통보문 원문 링크.

**화면 `/ops/weather` (국내 탭이 기본)**
- 상단: 전국 해상 특보 현황 지도(해상 특보구역 폴리곤을 등급 색으로) + 발표 시각.
- 본문: **항만 위험도 표** — 항만 / 현재 등급 / 근거 / 24h·48h·72h 전망 / 3~10일 전망(중기) / 다음 발표 예정 시각. 등급 높은 순 정렬, 관심 항만 고정.
- 항만 행을 열면: 시간대별 풍속·파고 곡선, 임계값 초과 구간, 특보 통보문 원문.
- **내 선적 일정 겹쳐 보기**: 5.5 딜 타임라인의 laycan을 불러와 위험 구간과 겹치면 경고. Laytime 계산기(5.1)에는 "해당 기간 특보 발효 이력"을 공제 항목 후보로 제안(자동 반영은 하지 않고 사용자가 선택).
- 홈 첫 화면: "오늘의 국내항" 스트립 — 주의 이상 항만만 표시, 없으면 "전 항만 정상 · 발표 시각".
- 고정 문구: "본 위험도는 기상청 특보·예보에 근거한 추정이며 공식 입출항 통제가 아닙니다. 실제 통제는 관할 VTS·지방해양수산청·터미널 공지를 확인하십시오." 관할 기관 공지 페이지 링크를 항만별로 제공한다.
- 해외 항만(싱가포르, 닝보 등)은 두 번째 탭에서 Open-Meteo 기반으로 유지.

**검증 케이스**
- 특보 없음 + 예보 임계값 미만 → 정상.
- 풍랑주의보 발효 → 높음, 근거에 발효 시각 표시.
- 예비특보(발효 예정 30시간 후) → 주의, 12시간 후 재평가 시 높음으로 승격.
- 태풍경보 → 통제 중 가능성 높음.
- 기상청 API 응답 실패 → 등급을 "정상"으로 표시하지 않고 "수집 실패 · 마지막 성공 시각" 표시.

## 12. [추가] 인터랙티브 항로·아비트라지 맵 — `/ops/route`

> 지도 위에서 선적항·양하항·선박을 고르면 **리드타임 · 운임 · 넷백**이 동시에 계산되고, 대안 항로·대안 도착지·대안 선형을 나란히 비교한다.
> 5.2(운임)·5.3(넷백)·5.8(TCE)의 계산 엔진을 그대로 재사용한다. 이 화면은 새 계산식을 만드는 곳이 아니라 **기존 엔진을 지도에 올리는 곳**이다.
> 배치: Phase 5 마지막. 단, 지도 컴포넌트 자체는 11장(특보 지도·AIS)과 공유하므로 Phase 2.5에서 먼저 만든다.

### 12.1 지도 기반

- 라이브러리: **MapLibre GL JS**(오픈소스). 동적 import로 지도 화면에서만 로드한다.
- 베이스맵: 무료로 쓸 수 있고 약관이 허용하는 벡터 타일을 조사해 선택한다(키 필요 여부·호출 한도·출처 표기 의무 보고). 스타일은 3장 토큰에 맞춘 **다크 해도풍 커스텀 스타일** — 육지는 `--bg-raised`, 바다는 `--bg`, 라벨 최소화, 등심선은 얇게.
- 투영: 태평양 횡단 항로가 끊기지 않게 중심 경도를 조정(동경 150° 부근)하거나 globe 뷰 지원 여부를 확인한다. 날짜변경선에서 선이 화면을 가로지르는 버그가 없어야 한다.
- 모바일: 지도가 상단 45%, 결과 패널이 하단 시트(드래그로 높이 조절).

### 12.2 해상 거리 엔진 — `src/lib/searoute/`

- 육지를 피해 가는 **해상 항로망(그래프) + 최단경로 탐색**으로 거리와 경로선을 구한다. 공개 해상 네트워크 데이터나 오픈소스 해상 라우팅 라이브러리를 조사해 채택하고 라이선스를 확인한다. 직접 만든다면 주요 변침점(해협·곶·운하)을 노드로 하는 그래프 + 대권거리 구간합.
- **통과 제약을 스위치로**: 수에즈, 파나마, 말라카(대안: 롬복·순다), 호르무즈, 바브엘만데브(홍해 회피 → 희망봉 우회), 대한해협, 토러스 해협. 스위치를 끄면 경로가 다시 계산된다.
- **검증 필수**: 공개 거리표가 있는 구간 10개 이상(예: 울산–싱가포르, 여수–닝보, 라스타누라–울산, 싱가포르–로테르담(수에즈/희망봉), 휴스턴–울산(파나마/희망봉))과 비교해 오차 3% 이내. 비교표를 `docs/distance-validation.md`로 남긴다. 기준을 못 맞추면 해당 구간은 "추정 오차 큼" 표기.
- 화면 표기: "추정 거리 · 정산은 계약상 거리표 기준". 사용자가 거리를 직접 덮어쓸 수 있다.

### 12.3 선박 프로필 — `src/data/vesselClasses.ts`

두 계열로 나눠 프리셋을 제공하고, 모든 값은 사용자가 수정할 수 있다.

| 계열 | 선형(예) | 주 화물 |
|---|---|---|
| **케미컬·석화 벌크** | 소형 케미컬(3~6kt), 중형(10~13kt), J19(19~20kt), 대형 파셀(25~40kt, 스테인리스/코팅) | SM, BZ, PX, MX, 톨루엔, MEG, 메탄올, MMA 등 |
| **정유(CPP·DPP·원유)** | MR(35~50kt), LR1(60~75kt), LR2/Aframax(80~115kt), Suezmax, VLCC | 납사, 휘발유, 항공유, 경유, 연료유, 원유 |

- 프로필 항목: DWT, 적재 가능 수량(화물 밀도 반영), 흘수(만재), LOA·폭, 서비스 속력(laden/ballast), 일일 연료 소모(항해/정박/하역), 통과 가능 운하.
- 프리셋 수치는 **공개 자료로 확인한 대표값**만 넣고 "대표값 · 실선 Q88 확인" 표기. 확인 못 한 항목은 비워 둔다. Q88 화면(5.7)에서 분석한 실제 선박을 프로필로 불러올 수 있게 한다.
- 화물을 고르면 밀도·IMO 선종 요구(Type 2/3)·코팅 유의사항이 "확인 필요" 수준으로 표시된다(적합 판정은 하지 않음).

### 12.4 계산 — 리드타임 · 운임 · 아비트라지

**리드타임** (`src/lib/leadtime.ts`)
- `총 리드타임 = 선박 수배·포지셔닝 일수 + 선적항 대기·하역 + 항해일수(거리 ÷ 속력 ÷ 24 × 기상 여유율) + 운하 대기 + 양하항 대기·하역`
- 항만 대기일수 기본값은 사용자 입력. 11.3의 AIS 묘박 척수와 11.4의 클로징 위험도를 옆에 띄워 판단을 돕는다(자동으로 일수에 더하지 않고 "대기 +n일 반영" 버튼으로 제안).
- 결과: laycan 기준 **도착 예정 구간(ETA 범위)**, 가격 산정 기간과의 관계(선적월 vs 도착월 — 월물 스프레드 노출 일수).

**운임** — 5.2 엔진 사용
- 입력 방식 3가지: $/MT 직접 입력 / Worldscale(flat·WS 사용자 입력) / **TCE 역산**(목표 TCE와 벙커가로 손익분기 운임 산출, 5.8 엔진).
- 벙커가는 11장의 LIVE 값을 기본으로 불러온다.
- 항로 대안별(예: 수에즈 vs 희망봉) 운임·일수·연료비·CO₂ 차이를 한 표에.

**아비트라지** — 5.3 엔진 사용
- 선적항 1개 → 도착지 후보 최대 6개를 지도에 동시에 그리고, 각 도착지의 **넷백($/MT)**을 항로선 굵기·색과 라벨로 표시. 가장 높은 넷백 항로가 강조된다.
- 도착지별 가격은 사용자 입력(유료 시세 수집 금지). 한 번 입력하면 저장되어 다음에 불러온다.
- **항해 중 가격 변동 리스크**: 리드타임 × 사용자가 넣은 일 변동성으로 넷백의 ±범위를 함께 표시.
- 손익분기선: "운임이 $x 오르면 A 도착지와 B 도착지의 순위가 바뀐다"를 문장으로 출력(규칙 기반).

### 12.5 항로 최적화

1. **경로 선택 최적화**: 통과 제약 조합별로 거리·일수·총비용(연료 + 운하 통행료 + 시간가치)을 계산해 최저 비용 경로를 추천. 운하 통행료는 사용자 입력(공식 요율 계산기는 링크 제공).
2. **속력 최적화**: 속력을 0.5노트 단위로 바꿔 가며 연료 소모(속력의 세제곱 근사, 근사임을 표기)와 일수를 계산 → 총비용 최소 속력과 "laycan을 맞추는 최저 속력"을 표시. 슬라이더를 움직이면 지도 위 ETA와 비용이 실시간으로 바뀐다.
3. **다항지 순서 최적화(케미컬 파셀 전용)**: 선적항 1~3개, 양하항 최대 6개와 항구별 물량을 넣으면 총 거리·총 일수가 최소인 기항 순서를 찾는다(항구 수가 적으므로 전수 탐색, 결과는 결정론적). 제약: 선적 완료 전 양하 불가, 항구별 laycan 창. 순서별 비교표와 지도 애니메이션.
4. **선형 선택**: 같은 물량을 소형 2항차 vs 대형 1항차로 보낼 때 톤당 운임·리드타임·재고 금융비용 비교.

최적화 결과에는 항상 **"왜 이 안이 선택됐는지"** 를 숫자 3개 이내로 설명한다(비용 차이, 일수 차이, 제약 충족 여부).

### 12.6 인터랙션·모션

- 지도에서 항구를 클릭해 선적항·도착지를 지정(검색도 가능). 항구는 프리셋 60~80개(국내 정유·석화 항만, 중국 화동·화남, 대만, 일본, 동남아, 인도, 중동, 유럽 ARA, 미 걸프) — 좌표는 검증 후 `src/data/ports.ts`.
- 경로선은 선택 순간 출발지에서 도착지로 **그려지며**(600~900ms), 그 위를 선박 아이콘이 리드타임 비율에 맞춰 이동한다. 타임 슬라이더(D+0 ~ D+n)를 끌면 선박 위치와 "오늘 날짜 기준 예상 위치"가 움직인다.
- 변침점 드래그로 경로 수동 수정 → 거리·일수·비용 즉시 재계산.
- 레이어 토글: 대안 경로 / ECA 구역 / 해상 특보(11.4) / AIS 탱커 밀도(11.3) / 고위험 해역(공개 고시 기준, 출처 표기).
- 비교 모드: 시나리오를 최대 4개 고정해 좌측 패널에 카드로 쌓고, 카드에 마우스를 올리면 해당 경로만 강조.
- 선박 계열 전환(케미컬 ↔ 정유) 시 항구 프리셋·화물 목록·선형이 함께 바뀐다.
- 성능: 지도 상호작용 60fps, 경로 재계산 100ms 이내(무거우면 Web Worker). `prefers-reduced-motion`에서는 이동 애니메이션 없이 결과만.
- 가상의 선박을 실제 AIS처럼 보이게 하지 않는다. 시뮬레이션 선박 아이콘은 실선(AIS)과 모양·색을 다르게 하고 범례에 "계획 항차(시뮬레이션)"로 표기.

### 12.7 출력

- 시나리오 요약 카드(항로, 거리, 일수, 운임, 넷백, 리스크)를 이미지·PDF로 내보내기 — 보고용 한 장.
- 공유 링크(URL에 시나리오 직렬화).
- "딜 타임라인으로 보내기"(5.5) / "Laytime 계산으로 보내기"(5.1) 버튼으로 다른 도구와 연결.

### 12.8 검증·완료 기준

- [ ] 거리 검증표 통과(12.2).
- [ ] 리드타임: 거리 2,500nm, 13노트, 여유율 5%, 선적 2일·양하 2일·대기 1일 → 항해 8.41일, 총 13.41일 (테스트).
- [ ] 다항지 최적화: 전수 탐색 결과가 수작업 계산과 일치하는 4항구 케이스 테스트.
- [ ] 속력 최적화: 연료가 0이면 최고 속력, 시간가치 0이면 최저 속력이 선택되는 경계 테스트.
- [ ] 수에즈 스위치를 끄면 경로가 희망봉으로 바뀌고 일수·비용이 함께 갱신된다.
- [ ] 날짜변경선·극지 근처·모바일 터치 드래그에서 지도 오류 없음.
- [ ] 운임·도착지 가격을 넣지 않은 상태에서는 넷백 순위를 표시하지 않고 "가격 입력 필요"로 안내한다.
